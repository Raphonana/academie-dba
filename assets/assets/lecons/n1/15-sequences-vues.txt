# Séquences, colonnes IDENTITY et vues
@duree 9
@resume Générer des identifiants et enregistrer une requête sous forme de vue.

## Le problème des identifiants
Pour ajouter un employé, il faut un nouvel `id_employe`. Prendre `MAX(id_employe) + 1` est une mauvaise idée : deux sessions en même temps obtiennent le même numéro, et l'une des deux reçoit ORA-00001.

## Les séquences
Une **séquence** est un générateur de numéros, sûr même avec des centaines de sessions simultanées :
```sql
CREATE SEQUENCE seq_employes START WITH 100 INCREMENT BY 1;

INSERT INTO employes (id_employe, nom, salaire, id_service)
VALUES (seq_employes.NEXTVAL, 'KAMGA', 600000, 20);

SELECT seq_employes.CURRVAL FROM dual;   -- le dernier numéro pris par MA session
```
- `NEXTVAL` donne le numéro suivant ;
- `CURRVAL` redonne le dernier numéro obtenu **par votre session** (il faut avoir appelé `NEXTVAL` avant).
! Une séquence peut laisser des **trous** : un numéro pris puis annulé par `ROLLBACK` n'est jamais réutilisé, et le cache peut être perdu au redémarrage. Ne l'utilisez pas pour des numéros qui doivent se suivre sans trou, comme des numéros de facture légaux.

## Les colonnes IDENTITY
Depuis Oracle 12c, une colonne peut générer seule sa valeur. Oracle crée et gère la séquence pour vous :
```sql
CREATE TABLE clients (
  id_client NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nom       VARCHAR2(100) NOT NULL
);
INSERT INTO clients (nom) VALUES ('SOCIETE ABC');
```
- `GENERATED ALWAYS` : Oracle donne toujours la valeur, et refuse qu'on la fournisse ;
- `GENERATED BY DEFAULT` : Oracle donne la valeur seulement si l'`INSERT` n'en fournit pas.

## Les vues
Une **vue** est une requête enregistrée avec un nom. On l'interroge comme une table, mais elle ne stocke **aucune donnée** : Oracle exécute la requête à chaque fois.
```sql
CREATE OR REPLACE VIEW v_employes_services AS
SELECT e.nom, e.prenom, s.nom AS service, s.ville
FROM   employes e
JOIN   services s ON s.id_service = e.id_service;

SELECT * FROM v_employes_services WHERE ville = 'Douala';
```
Les vues servent à :
- **simplifier** : une jointure complexe écrite une fois pour toutes ;
- **sécuriser** : donner accès à la vue sans les colonnes sensibles (ici, pas de salaire), plutôt qu'à la table ;
- **stabiliser** : l'application lit la vue, et on peut réorganiser les tables derrière.
> Ajoutez `WITH READ ONLY` à la fin de la définition pour interdire toute modification à travers la vue.

=== QUIZ
? Pourquoi ne pas générer les identifiants avec MAX(id) + 1 ?
- C'est interdit en SQL
+ Deux sessions simultanées peuvent obtenir le même numéro
- MAX ne fonctionne pas sur les nombres
- C'est trop rapide
= Entre la lecture du MAX et l'INSERT, une autre session peut faire la même chose. Une séquence garantit des numéros uniques.

? Que renvoie seq_employes.CURRVAL ?
- Le prochain numéro de la séquence
+ Le dernier numéro obtenu par votre session avec NEXTVAL
- Le dernier numéro pris par n'importe quelle session
- Le nombre total de numéros générés
= `CURRVAL` est propre à votre session, et n'est disponible qu'après un premier `NEXTVAL`.

? Une séquence peut-elle avoir des trous ?
+ Oui, par exemple après un ROLLBACK ou un redémarrage
- Non, jamais
- Seulement si on la supprime
- Seulement avec INCREMENT BY 2
= Un numéro donné par `NEXTVAL` est consommé, même si la transaction est annulée.

? Avec GENERATED ALWAYS AS IDENTITY, que se passe-t-il si on fournit soi-même une valeur dans l'INSERT ?
- La valeur fournie est utilisée
+ Oracle refuse l'INSERT par une erreur
- La valeur est ignorée sans message
- La séquence est remise à zéro
= `ALWAYS` réserve la génération à Oracle. Utilisez `BY DEFAULT` pour pouvoir fournir une valeur.

? Que stocke une vue ?
- Une copie des données au moment de sa création
+ Uniquement la requête : les données sont lues dans les tables à chaque appel
- Un index sur les tables
- Une sauvegarde de la table
= Une vue est une requête nommée. (Les vues **matérialisées**, qui stockent un résultat, seront vues plus tard.)

?? Créez une séquence `seq_services` qui commence à 50 et avance de 10, puis utilisez-la pour ajouter le service « Juridique » à Bafoussam.
>> CREATE SEQUENCE seq_services START WITH 50 INCREMENT BY 10;
>> INSERT INTO services (id_service, nom, ville) VALUES (seq_services.NEXTVAL, 'Juridique', 'Bafoussam');
== SELECT id_service, nom, ville FROM services ORDER BY id_service
~ `CREATE SEQUENCE … START WITH 50 INCREMENT BY 10`, puis `seq_services.NEXTVAL` dans l'INSERT.

?? Créez une vue `v_annuaire` qui montre le nom, le prénom et l'email des employés, mais pas leur salaire.
>> CREATE OR REPLACE VIEW v_annuaire AS SELECT nom, prenom, email FROM employes
== SELECT nom, prenom, email FROM v_annuaire ORDER BY nom
~ `CREATE OR REPLACE VIEW v_annuaire AS SELECT …`

?? Créez une table `clients` avec une colonne `id_client` générée automatiquement (IDENTITY, clé primaire) et une colonne `nom` VARCHAR2(100), puis ajoutez les clients ALPHA et BETA, dans cet ordre.
>> CREATE TABLE clients (
>>   id_client NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
>>   nom       VARCHAR2(100) NOT NULL
>> );
>> INSERT INTO clients (nom) VALUES ('ALPHA');
>> INSERT INTO clients (nom) VALUES ('BETA');
== SELECT id_client, nom FROM clients ORDER BY id_client
